# Wi-Fi (PTP/IP) — план

Цель: обе программы управляют ZV-E10 без кабеля — режим камеры PC Remote «Wi-Fi Access Point» (через роутер) и «Wi-Fi Direct». Проверено опытом (скрипт на Python, 2026-10-24): SSDP-поиск, сопряжение по GUID, тот же сеанс Sony, превью ~22 к/с, запись с подтверждением ~0,8 с, события 0xC203.

Решения (мои):
- Подключение выбирается само: камера на кабеле — USB; иначе сопряжённая камера в сети — Wi-Fi. Отдельного переключателя режимов нет; в настройках — «Подключаться по Wi-Fi» и «Забыть камеру».
- GUID программы создаётся один раз и хранится в настройках; имя для камеры — «ZV-E10 Viewer».
- Сопряжение — кнопкой на экране ожидания: программа ищет камеру и стучится, пока на камере включено Pairing.
- Сеанс Sony не меняется: транспорт PTP/IP сам открывает сессию PTP (OpenSession), как это делал ImageCaptureCore для USB, с короткими повторами.

## Mac
1. ZVCore/PTPIP: пакеты PTP/IP, чтение потока по пакетам, сборка ответа операции (Start/Data/End/Response, чужие транзакции — мимо), разбор ответа на Init, события; SSDP — запрос и разбор ответа. Тесты.
2. ZVCamera: PTPIPTransport (Network.framework, два TCP-соединения, последовательные транзакции, тайм-аут, ping/pong), WiFiDiscovery (SSDP по UDP). zv-probe --wifi для проверки на камере.
3. ZVViewer: источник подключения Wi-Fi рядом с USB, сопряжение, «· Wi-Fi» в плашке, настройки, NSLocalNetworkUsageDescription. API: transport в /state, действие pairWiFi.
4. Сквозные тесты e2e.py и e2e_photo.py по Wi-Fi.

## Android
5. PtpIpTransport (Socket), поиск SSDP, сопряжение, тот же выбор USB/Wi-Fi. Проверка на планшете, в том числе Wi-Fi Direct.
