# ZV-E10 Viewer — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Лёгкое macOS-приложение в DMG: при запуске само находит Sony ZV-E10 по USB, показывает live view и даёт менять настройки через Fn-меню поверх видео.

**Architecture:** Swift Package из четырёх целей.
- `ZVCore` — чистая логика без фреймворков камеры: разбор PTP и данных Sony, подписи значений, сессия камеры (actor) поверх протокола `PTPTransport`. Покрыт тестами на реальных дампах камеры и на фейковой камере.
- `ZVCamera` — `PTPTransport` через ImageCaptureCore и поиск камеры.
- `ZVViewer` — SwiftUI-приложение.
- `zv-probe` — консольная утилита для проверок на живой камере.

Скрипты собирают .app и DMG без Xcode-проекта.

**Tech Stack:** Swift 6.2 (Xcode 26), SwiftUI, ImageCaptureCore, ImageIO, Swift Testing, codesign, hdiutil.

**Spec:** `docs/superpowers/specs/2026-10-24-zv-e10-viewer-design.md`

## Global Constraints

- Минимальная macOS — 14.0: `platforms: [.macOS(.v14)]`, `LSMinimumSystemVersion` 14.0. Проверка — на macOS 27, Apple Silicon (сборка под arm64 хоста).
- Все цели в Swift language mode 5 (`swiftLanguageModes: [.v5]`). Внешних зависимостей нет, только системные фреймворки.
- Название «ZV-E10 Viewer», bundle id `local.zve10viewer`, версия 0.1.0. Тексты интерфейса и комментарии в коде на русском, идентификаторы на английском.
- В камеру никогда не отправляется значение, которого нет в текущем списке или диапазоне свойства. Запись в свойство с `isWritable == false` не отправляется вообще.
- outData у `0x9205` и `0x9207` — только само значение по типу свойства: ImageCaptureCore сам оборачивает его в контейнер. Полный PTP-контейнер в outData запрещён.
- Константы:
  - версия протокола Sony — 0x12C;
  - handle live view — 0xFFFFC002;
  - PriorityMode 0xD25A = 1 (INT8);
  - пауза после рукопожатия — 3 с;
  - подтверждение записи — до 2,5 с, опрос каждые 150 мс.
- `spike/ptp-probe` — только справочник, из него ничего не импортируется.
- Шаги «на камере» выполняются с подключённой ZV-E10 (PC Remote, USB) и вместе с пользователем. Любая изменённая при проверке настройка возвращается обратно, и это подтверждается чтением с камеры.

## Review Focus

1. **Настройку крутят на самой камере, пока программа открыта.** Значение в программе обновляется примерно за секунду. Тест: `propertyChangedEventPublishesSnapshot` (Задача 4).
2. **Кабель выдернут или камера выключена во время live view или записи настройки.** Программа не зависает и не падает, возвращается на экран ожидания, после подключения снова показывает видео. Тест: `disconnectFinishesSnapshotsAndFailsSet` (Задача 5), проверка на камере — в Задачах 6 и 7.
3. **Колесо мыши быстро крутят над значением.** В камеру уходит только последнее значение и только из разрешённого списка. Тесты: `rapidSubmitsWriteFirstAndLast` (Задача 5), `neighbourClampsAtEnds` (Задача 3).
4. **Сменили режим камеры или объектив, и поменялись списки значений.** Программа берёт свежие списки. Значение без подписи показывается как `#N`, без падения. Тесты: `optionsComeFromGivenPropertyOnly`, `unknownValueFallsBackToNumber` (Задача 3).
5. **Настройку меняют в первые 3 с после подключения или когда камера её не даёт менять** (например, экспокоррекция в M с фиксированным ISO). Ничего не отправляется, плитка неактивна. Тесты: `setBeforeReadyThrowsAndSendsNothing`, `setRejectsDisplayOnlyProperty` (Задача 5).

Раскладка:
- `fnTopRow`: shutter, aperture, iso, whiteBalance, exposureComp, focusMode;
- `fnBottomRow`: focusArea, metering, pictureProfile, creativeStyle, dro, `.allSettings`;
- `infoLine`: shutter, aperture, iso, whiteBalance, exposureComp, focusMode.

Подписи значений (`ValueFormatter`):
- Числовые:
  - **shutter.** 0 → «BULB». num = v >> 16, den = v & 0xFFFF. Если num == 1 и den > 1 → «1/den». Иначе секунды num/den, не больше одного знака после запятой, без «.0», плюс знак `"`.
  - **aperture.** 0 или 0xFFFF → «f/--». Если v % 100 == 0 → «f/(v/100)». Иначе «f/» и один знак после запятой.
  - **iso.** Если (v & 0xFFFFFF) == 0xFFFFFF → «AUTO», иначе число v & 0xFFFFFF.
  - **exposureComp.** 0 → «±0.0». Иначе знак («+» или «−», U+2212) и |v|/1000 с одним знаком после запятой.
  - **colorTemperature.** «v K».
  - **wbShiftAB, wbShiftGM.** Сдвиг = (v − 192) / 4: 0 → «0», иначе со знаком (+/−) и без лишних нулей. Какой знак — A, а какой — B, сверить в Задаче 8.
- Перечисления:
  - **whiteBalance.**
    - 2 AWB, 4 Дневной, 0x8011 Тень, 0x8010 Облачно, 6 Лампа;

**Interfaces:**

  - `CameraSession`, `SessionError`, `TransportError`, `FakeCamera`, `readySession` (Задача 4);
  - `LiveViewFrame`, `Sony` (Задача 2).
- Produces:
  - `enum SetResult: Equatable, Sendable { case confirmed, notApplied(actual: Int64?) }`
  - Методы `CameraSession`:
    - `func set(_ code: UInt16, to value: Int64) async throws -> SetResult`;
    - `func toggleRecording() async throws -> Bool`;
    - `func nextLiveViewFrame() async throws -> Data`.
  - `actor WriteCoalescer`:
    - `init(write: @escaping @Sendable (UInt16, Int64) async -> Void)`;
    - `func submit(_ code: UInt16, _ value: Int64)`, `func isPending(_ code: UInt16) -> Bool`, `func waitUntilIdle() async`.

Поведение:
- **`set`**:
  1. Проверки, по порядку:
     - `!isReady` → `notReady`;
     - свойства нет или `!isWritable` → `notWritable(code)`;
     - значения нет в `settableValues` (или в `range` с учётом шага) → `valueNotAllowed`.
  2. Отправить `0x9205 [code]`, outData = `PTPValue.encode(value, type: dataType)`. Ответ не OK → `operationFailed`.
  3. Вызывать `refresh()` каждые `pollInterval`, но не дольше `confirmTimeout`:
     - `current == value` → `.confirmed`;
     - время вышло → `.notApplied(actual:)`.
- **`toggleRecording`**:
  1. `!isReady` → `notReady`.
  2. `0x9207 [0xD2C8]` с outData `[0x02, 0x00]`, затем то же с `[0x01, 0x00]`.
  3. Ждать изменения `0xD21D`, опрос как в `set`, и вернуть `current == 1`.
- **`nextLiveViewFrame`** — цикл `0x1009 [0xFFFFC002]`:
  - OK и `LiveViewFrame.jpeg` не nil → вернуть JPEG;
  - `accessDenied` → пауза 20 мс; `invalidObjectHandle` → пауза 50 мс;
  - любой другой код → `operationFailed`;
  - учитывает отмену задачи.
- **`WriteCoalescer`**:
  - по каждому коду идёт не больше одной записи одновременно;
  - `submit` во время записи заменяет отложенное значение;
  - после записи, если есть отложенное значение, пишет его.
