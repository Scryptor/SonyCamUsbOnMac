# Порядок плиток в ленте камер — дизайн

Пользователь (2026-10-26, после 0.7.0): «когда нажимаешь на камеру какую-нибудь допустим 3 шт, он в списке ее квадратик
вверху показывается, прыгает наверх, это же не удобно? Надо чтобы их можно было поменять местами перетаскиванием, но
чтобы сами по себе при выборе они не меняли места».

Проверено: в 0.7.0 так и есть на Mac и на планшете. Главная плитка всегда рисуется первой. Выбранная камера уходит
наверх, прежняя главная — в конец ленты. Вопросы по дизайну не задаём (память `work-autonomously`): решения ниже мои.

## Решения

### 1. Порядок постоянный

- Плитки ленты — главная и камеры ленты, на связи и «нет связи» — идут в порядке знакомых камер. Это массив `cameras` в
  настройках: новая камера добавляется в конец, остальные обновляются на месте, сами записи не переставляются.
- Щелчок (касание) по плитке делает камеру главной на её месте: синяя рамка переходит к ней, ни одна плитка не
  двигается. Прежняя главная остаётся там, где была.
- Камера, которая впервые попала в ленту, встаёт в конец. Убрали из ленты и вернули — она снова на своём месте среди
  остальных: запись знакомой камеры никуда не делась.
- Главная пропала — главной становится первая сверху камера ленты на связи. Руководство так и говорит: «первая камера
  из ленты». Теперь «первая» — это верхняя.

### 2. Перетаскивание

- **Mac.** Любую плитку, и главную тоже, тащат мышью. Пока тащите, соседние плитки сразу раздвигаются. Отпустили —
  порядок запомнен. Щелчок без движения, как раньше, делает камеру главной. Правый клик — меню, как раньше.
- **Планшет.** Долгое нажатие поднимает плитку: она чуть увеличивается, у камеры ленты, как раньше, открывается меню.
  Повели пальцем — меню закрывается, плитка едет за пальцем, соседние раздвигаются. Отпустили — плитка на новом месте.
  Долгое нажатие без движения — только меню, как раньше. У главной меню нет, её можно только перетащить. Касание
  цепочки по-прежнему только связывает и отвязывает камеру.
- Порядок хранится там же, в массиве `cameras`: перетащили — запись камеры переставлена. Формат записи прежний, старые
  версии его читают.

### 3. Модель (без интерфейса — проверяется тестами)

- Mac, `CameraRoster` (ZVCore):
  - `stripOrder(_ ids: [String]) -> [String]` — те же id в порядке знакомых камер. Id без записи остаются в конце, в
    том же порядке, в каком пришли.
  - `move(_ id: String, onto target: String)` — запись `id` встаёт на место `target`. Если тащили вниз — после
    `target`, если вверх — перед ним. Для плиток ленты это и есть «встала на место той, на которую навели», даже когда
    между ними в массиве есть камеры не из ленты.
- Android, `CameraBook`: `stripOrder(ids: List<String>): List<String>` и `moved(id: String, onto: String): CameraBook` —
  то же.

### 4. API (Mac)

- `/state` → `strip` — в порядке плиток (раньше главная шла первой).
- Действие `moveInStrip {id, onto}` — как будто плитку `id` перетащили на плитку `onto`.

## Проверка

- Модульные тесты на `stripOrder` и `move` / `moved`: вниз, вверх, через камеры не из ленты, неизвестные id, порядок
  после записи в JSON и чтения обратно.
- Mac, `scripts/e2e_strip.py`, на виртуальных A, B, C:
  - щелчок по плитке не меняет порядок;
  - `moveInStrip` меняет;
  - после переключения главной порядок прежний;
  - главная пропала — главной стала верхняя камера ленты.
- Mac: перетаскивание мышью по-настоящему, если получится послать события мыши; иначе — просим пользователя.
- Планшет: долгое нажатие и перетаскивание через `adb shell input motionevent DOWN/MOVE/UP`; касание по плитке не
  меняет порядок; долгое нажатие без движения — меню; порядок сохраняется после перезапуска.

## Что не делаем

- Перетаскивание в списке камер (подсказка строки состояния): там порядок по тому, когда подключались, как раньше.
- Отдельную кнопку «упорядочить» и ручки для перетаскивания.

## Что выяснилось при проверке

- Mac, `scripts/e2e_strip.py` — 25 из 25 на итоговой сборке:
  - щелчок по плитке порядок не меняет;
  - `moveInStrip` переставляет, следующий щелчок перестановку не сбивает;
  - убранная из ленты и возвращённая камера встала на своё место;
  - главная пропала — главной стала верхняя камера ленты.
- Верхнюю камеру ленты теперь берут оба места, где камера ленты заменяет главную: «главная пропала» и «последняя не
  ответила». Раньше бралась первая по списку.
- Mac: перетаскивание — свой жест (DragGesture), а не системное `onDrag`: у того нет события «перетаскивание
  кончилось». Плитка едет над лентой за мышью, на её месте бледный след, соседние раздвигаются.
  - Настоящей мышью не проверено: система не даёт этому процессу посылать события мыши, а разрешение без пользователя
    я не запрашивал. Проверит пользователь.
- Планшет, касаниями (`input motionevent`), на виртуальных A, B, C:
  - касание не меняет порядок;
  - долгое нажатие без движения — меню «Сделать главной», «Убрать из ленты»;
  - нижнюю плитку перетащили на два места вверх, главную — на одно вниз;
  - цепочка меняет только связь;
  - после перезапуска программы порядок тот же.
  - Пока открыто меню, `uiautomator dump` видит только его окно: проверять порядок плиток — после того, как меню
    закрыто.
- Android: 239 модульных тестов (13 новых — порядок, перестановка, жест без экрана).
