# Несколько камер: виртуальные камеры и выбор камеры — дизайн (этапы 0–1)

Просьба пользователя (2026-10-25, после 0.6.0): обсудили мультикамерность. Решили идти этапами: 1 — выбрать одну
камеру из нескольких, 2 — несколько на связи, 3 — управлять группой. У пользователя одна камера, поэтому сначала
этап 0 — несколько разных виртуальных камер для проверки. Задание: «Делай этап 0 (несколько разных виртуальных
камер, порт в программах, API) и этап 1 (выбор камеры) на Mac и планшете». Вопросы по дизайну не задаём (память
`work-autonomously`): решения ниже — мои.

## Что было

- Кабель: `ConnectionTracker` подключает первую камеру на шине, остальные ждут, пока первую не отключат.
- Wi-Fi: одна камера в памяти (`wifiHost`, `wifiCameraName`, последнее — заодно флаг «сопряжена»). Поиск (SSDP)
  находит всех, кто ответил; программа стучится сначала по последнему адресу, потом по найденным, — к первой, что
  согласилась. Порт PTP/IP — всегда 15740.
- У программы одно имя для камер (GUID); камера помнит сопряжение сама — несколько камер сопрягаются уже сейчас.

## Этап 0 — виртуальные камеры

`scripts/fake_camera.py` (новые параметры, прежние запуски работают как раньше):

- `--name` — имя камеры в ответе на приветствие (как «ZV-E10»); `--serial` — серийный номер в DeviceInfo; по нему
  программа отличает камеры. По умолчанию — как в дампе.
- `--mark flip|flop|rotate` — кадр отражён по горизонтали, по вертикали или повёрнут: на снимке экрана видно, чья
  картинка.
- `--battery N` — заряд; `--mode photo|video` — режим на старте (буква M).
- `--ssdp` — отвечает на поиск в сети, как камера Sony: `LOCATION` с адресом, `USN` со своим uuid и
  `X-PTPIP-Port` — порт PTP/IP (заголовок шлют только виртуальные камеры).
- `--busy` — приветствие не отвечает никогда (как камера, которая держит прошлое подключение);
  `--pairing` — незнакомому GUID отвечает через 3 с (как будто на камере нажали «ОК» в Pairing), потом помнит его.

`scripts/fake_cameras.py` — несколько камер одной командой: по умолчанию A, B и C на портах 15740–15742 одного адреса,
у B кадр отражён, у C повёрнут, разные серийные номера, заряд и режим. `--host` — адрес (для планшета — адрес Mac в
сети), `--count`, `--ssdp`. Ctrl+C гасит все.

Программы: адрес камеры — хост и порт. У настоящих камер порт всегда 15740, другой бывает только у виртуальных:
из `X-PTPIP-Port` в ответе на поиск, из тестового адреса (`ZV_PTPIP_HOST` на Mac и `ptpipHost` на планшете понимают
`хост:порт`) и из памяти о камере.

## Этап 1 — список камер и выбор

### Что программа помнит о камере

Ключ настроек `cameras` — JSON-массив, `preferredCamera` — id камеры, к которой подключались последней:

```json
{"id": "3f2a9c0d1e4b5a67", "aliases": ["9b8c…"], "name": "ZV-E10", "model": "ZV-E10",
 "host": "192.168.1.40", "port": 15741, "paired": true, "lastUsed": 1761400000}
```

- `id` — отпечаток: SHA-256 от UTF-8 строки `sn:<серийный номер из DeviceInfo>`, 16 первых знаков в hex. Сам номер не
  хранится нигде. `aliases` — другие отпечатки той же камеры: `usn:<uuid из USN>` по Wi-Fi и `sn:<серийный номер
  USB>`, если система отдаёт его до подключения и он не совпал с DeviceInfo.
- `name` — как назвали; по умолчанию модель, а если такое имя уже у другой камеры — «ZV-E10 2», «ZV-E10 3»…
- `host`, `port` — где была по Wi-Fi в последний раз (`port` пишется, только если не 15740); `paired` — сопряжена;
  `lastUsed` — секунды Unix.
- Незнакомые поля и записи без `id` при чтении пропускаются.
- Переход со старой памяти: ключа `cameras` нет, а `wifiCameraName` есть → одна запись `id: "legacy"`, имя и модель —
  `wifiCameraName`, адрес — `wifiHost`, `paired: true`. Её получает первая камера, подключившаяся по Wi-Fi (сначала —
  с тем же адресом, иначе любая: адрес мог смениться, а прежние версии помнили одну камеру); `id` становится
  настоящим отпечатком, имя остаётся. Пока такая запись есть, сопряжённой считается любая незнакомая камера в сети —
  прежние версии так и стучались. `wifiHost` и `wifiCameraName` по-прежнему пишутся при каждом подключении по Wi-Fi
  — для прежних версий.

### Кого видно сейчас

- Кабель: по записи на каждое устройство на шине: модель — имя устройства, отпечаток — `sn:` от серийного номера USB,
  если система его даёт.
- Wi-Fi: ответы на поиск (хост, порт, отпечаток `usn:`). Камера видна 30 с после последнего ответа. Поиск идёт, как и
  раньше, пока нет связи; а ещё — когда открыт список камер: сразу и раз в 10 с.
- Чья это запись: отпечаток совпал с `id` или `aliases`; иначе по Wi-Fi — тот же хост и порт; иначе камера незнакомая.

### Список

Порядок: текущая; видимые — сначала на кабеле, потом по Wi-Fi, каждые по `lastUsed` (незнакомые в конце); невидимые
знакомые — по `lastUsed`. Строка: имя (незнакомая по кабелю — модель, по Wi-Fi — «Камера в сети»), как подключена
(«по кабелю», «Wi-Fi · 192.168.1.40», порт — если не 15740) и состояние:

| Состояние | Подпись | Действие |
|---|---|---|
| текущая | «на связи» / «подключаю…» | — |
| на кабеле | «свободна» | «Подключить» |
| по Wi-Fi, сопряжена | «свободна» | «Подключить» |
| по Wi-Fi, не сопряжена | «нужно сопряжение» | «Сопрячь» — сопряжение только с ней |
| сопряжение с ней идёт | «сопрягаю…» | — |
| знакомая, не видна по Wi-Fi | «не видна в сети» | «Подключить» — одна попытка по последнему адресу |
| знакомая, только кабель | «не подключена» | — |

Правый клик на Mac, долгое нажатие на планшете: «Переименовать…» и «Забыть» (у текущей «Забыть» нет: она на связи).
«Забыть» убирает запись и снимает предпочтение, если оно было на ней. Внизу списка — «Сопрячь новую камеру…» (как
прежнее «Сопрячь с камерой…»: с любой камерой в режиме Pairing — сначала с несопряжёнными, потом со знакомыми; камера
на связи при этом отключается).

### Как подключается

1. Связи нет — подключается сама, как раньше: камера на кабеле; по Wi-Fi — сначала предпочтённая (её последний адрес),
   потом остальные видимые сопряжённые.
2. Связь есть — сама не переключается никогда; новые камеры просто появляются в списке.
3. Выбрали другую в списке — текущий сеанс закрывается, программа подключается к выбранной; она становится
   предпочтённой. Выбор камеры по Wi-Fi работает, даже когда на кабеле есть другая. Пока идёт запись — не
   переключает: «Идёт запись — остановите её, чтобы переключить камеру».
4. Каждое подключение делает камеру предпочтённой и обновляет `lastUsed`, адрес и сопряжение.
5. Камера по Wi-Fi оборвалась — тихое восстановление, как раньше; не вышло — правило 1.
6. Приветствие — только сопряжённым камерам или при сопряжении (как раньше, теперь у каждой камеры своё).
7. Настройки → Wi-Fi: «Забыть» → «Забыть сопряжение» — новый GUID, все камеры становятся несопряжёнными, имена
   остаются.

### Где на экране

- Строка состояния: «<имя камеры> · Wi-Fi» вместо модели. Щелчок, как и раньше, — подсказка «Подключение»; в ней
  сверху — «Камеры»: список и «Сопрячь новую камеру…», ниже — то, что было (адреса, сигнал, отладка).
- Экран ожидания: блок «Камеры» с тем же списком, если в нём есть хоть одна камера.
- Статус при переключении: «Подключаю «<имя>»…»; не ответила — «<имя>» не отвечает», дальше — правило 1.
- Экран ожидания: «Ищу камеру в сети…» («Ищу камеры в сети…», если сопряжённых несколько) — без модели: программа для
  разных камер Sony, а какие именно ищем, видно в списке.

### API (Mac)

- `/state`: `cameras` — список (`id`, `name`, `model`, `link`: `usb` / `wifi`, `host`, `port`, `state`: `current` /
  `available` / `needsPairing` / `offline`, `paired`), `currentCamera` — id или null.
- Действия: `selectCamera {id}`, `renameCamera {id, name}`, `forgetCamera {id}`, `pairCamera {id}`,
  `searchCameras` — поиск в сети сейчас.

## Проверка

Виртуальные A, B, C (у B — `--pairing`, у C — `--busy` в отдельном прогоне): список и состояния, выбор и
переключение, предпочтение после перезапуска, переименование, «Забыть», сопряжение одной камеры, обрыв выбранной,
выбор по Wi-Fi при камере на кабеле — на настоящей камере, без записи и снимков. На Mac — через API, на планшете —
касаниями, виртуальные камеры — на адресе Mac в сети.

## Что выяснилось при проверке

- Mac, виртуальные A, B, C через поиск в сети: прежняя запись о камере перешла к первой найденной; сопряжение одной B
  («сопрягаю…», 6 с); переключение (3 с); имена и строка состояния; после перезапуска — последняя выбранная; отказ при
  записи; занятая C — сопряжение ждёт, отмена возвращает к последней; пропала текущая — минута тихого восстановления,
  потом другая сопряжённая (через 72 с); вернулась — программа на ней не переключается; «Забыть» и снова сопрячь;
  «Сопрячь новую камеру…» выбирает новую, а не знакомые. `scripts/e2e_cameras.py` — 15 проверок.
- Планшет, те же камеры на адресе Mac в сети: 10 проверок касаниями плюс отказ при записи и «Забыть сопряжение» —
  имена остались, камеры стали «нужно сопряжение», «Ищу камеру в сети…» без сопряжённых не показывается.
- API `pairWiFi` раньше отказывал при камере на связи — теперь как кнопка: сеанс закрывается, ищется новая.
- Не проверено: две камеры на кабеле (виртуальной USB-камеры нет) и выбор камеры по Wi-Fi при настоящей камере на
  кабеле.

## Что не делаем на этом этапе

- Несколько камер на связи сразу (этап 2) и групповое управление (этап 3).
- Пресеты по камерам: они общие, со своими списками для фото и видео.
- Выбор между двумя камерами на кабеле проверяется только тестами: двух камер нет.
