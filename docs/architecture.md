## Общая схема

```
ZVViewer (SwiftUI)
  LiveScreen, FnMenu, AllSettingsPanel, …   ← ScreenState: что открыто на экране
          │
  CameraController (@MainActor)              ← поиск камеры, live view, записи, пресеты, съёмка
          │
ZVCore
  CameraSession (actor)                      ← рукопожатие, свойства, запись, кнопки, превью, снимок
          │  PTPTransport (протокол)
ZVCamera
  ICCameraTransport    PTPIPTransport (actor) ← USB: ImageCaptureCore; Wi-Fi: PTP/IP поверх Network
          │                   │
     камера по USB     камера по Wi-Fi (WiFiDiscovery находит её по SSDP)
```

`ZVCore` ничего не знает про ImageCaptureCore, сеть и интерфейс. Поэтому вся логика протокола и сеанса проверяется тестами на поддельной камере.

## Модули

Swift-пакет, четыре цели и тесты. Сторонних зависимостей нет.

### ZVCore — логика без интерфейса

| Папка | Что внутри |
|---|---|
| `PTP/` | `ByteReader` — чтение little-endian и строк PTP; `PTPValue` — значения по типу PTP; `PTPContainer` — контейнер команды, разбор ответа, коды ответов |
| `Sony/` | `SonyCodes` — коды операций и свойств; `DeviceInfo`, `SonyExtInfo` — ответы `0x1001` и `0x9202`; `SonyProperty` и `SonyPropertyParser` — свойства из `0x9209`; `LiveViewFrame` — JPEG из ответа превью |
| `Session/` | `PTPTransport` — протокол транспорта, ошибки, тайминги; `CameraSession` — сеанс; `ConnectionTracker` — какую камеру подключать и когда повторять; `WriteCoalescer` — одна запись на свойство за раз |
| `Settings/` | `SettingID` и `SettingGroup` — 24 настройки и 6 групп; `SettingCatalog` — раскладка меню Fn и строки значений; `SettingOptions` — допустимые значения и соседнее значение; `ValueFormatter` — подписи значений; `InputFilters` — колесо мыши и площадка сдвига баланса белого |
| `Presets/` | `Preset`, `PresetCatalog` — что входит в пресет; `CameraSession.apply` — применение с учётом зависимостей |
| `Photo/` | `CaptureMode` — фото или видео и пары режимов; `ObjectInfo` — ответ `0x1008`; `FileNaming` — свободные имена файлов; `PhotoCapture` — снимок и скачивание |
| `Histogram/` | `LumaHistogram` — гистограмма яркости |
| `Automation/` | `HTTPMessage` — разбор запроса и сборка ответа; `AutomationAction` — команды API |
| `PTPIP/` | `PTPIP` — пакеты PTP/IP (приветствие, команды, данные, события) и `isCameraAccessPoint` — камера ли это в режиме Wi-Fi Direct (адрес `192.168.122.1`), `PTPIPPacketReader` — сборка пакетов из потока TCP, `PTPIPTransaction` — ответ на одну операцию; `SSDP` — запрос поиска и разбор ответа камеры |

В `Photo/` — `ShootingMode`: фото, видео или S&Q по `0x500E` и режим с той же буквой P/A/S/M для переключателя; и `SlowQuick` — частота съёмки S&Q по самой длинной допустимой выдержке и подпись «×4 медленнее». В `Settings/` есть и `RecordingModes`: режимы записи обоих форматов одним списком («4K 25p 100M», «HD 100p 100M»…) — для текущего формата из ответа камеры, для второго по таблице кодов той же системы (PAL или NTSC). Лента значений берёт варианты у `CameraController.stripOptions`, а выбор отдаёт в `choose`: у режима записи значение — код «формат × 256 + параметры», и `setRecordingMode` пишет сначала формат, потом параметры. И `WhiteBalanceTemperature`: что показать о цветовой температуре при текущем режиме баланса белого — ручную, примерную для пресета или «авто».

### ZVCamera — связь с камерой

- `CameraDiscovery` — `ICDeviceBrowser`, отбирает камеры Sony (VID `0x054C`), отдаёт поток событий «появилась» и «пропала». Там же `ICCameraDevice.openSession(timeout:)`.
- `ICCameraTransport` — реализация `PTPTransport`. Шлёт команды с таймаутом 8 с, превращает PTP-события в поток, по `didRemove` переходит в состояние «отключено». Становится делегатом устройства ещё до открытия сессии. `close()` закрывает сессию (не дольше 3 с) и отвязывает делегата.
- `PTPIPTransport` (actor) — `PTPTransport` по Wi-Fi: два соединения `NWConnection` (`PTPIPChannel`), приветствие, канал событий, OpenSession с коротким тайм-аутом и повтором. Транзакции строго по одной; тайм-аут — на паузу между пакетами, а не на весь ответ: большой снимок идёт долго, но непрерывно. Два тайм-аута подряд — обрыв. Состояние `waiting` у `NWConnection` обрывом не считается. `localHost()` — адрес Mac в этом соединении.
- `PTPIPIdentity` — GUID и имя программы для камеры; GUID создаётся один раз и хранится в `UserDefaults` (набор `local.zve10viewer`), его же берёт `zv-probe`.
- `WiFiDiscovery.search(seconds:)` — SSDP-поиск через сокет BSD с повтором запроса каждые 0,7 с.

## Как это работает

### Подключение

1. `CameraDiscovery` сообщает, что появилась камера Sony. `ConnectionTracker.appeared` решает, подключаться ли: если уже работаем с другой подключённой камерой, новая ждёт.
2. `CameraController.connect` создаёт `ICCameraTransport` (он сразу становится делегатом устройства), `CameraSession` и `WriteCoalescer`. Фаза — `connecting`.
3. Открывается сессия ImageCaptureCore, затем `CameraSession.start()`: рукопожатие Sony, PriorityMode, первое чтение свойств, подписка на события.
4. Фаза — `settling`. Запускаются поток свойств и цикл превью: видео уже идёт, но настройки ещё неактивны.
5. `waitUntilReady()` ждёт 3 секунды и перечитывает свойства. Фаза — `ready`.

Что может пойти не так:

- **Камера не в режиме PC Remote** (`SessionError.notPCRemote`) — фаза `notPCRemote`, экран с подсказкой.
- **Попытка сорвалась** — `ConnectionTracker.failed` отвечает «повторить через 2, 4, 8, 10, 10… с», пока камера подключена. На экране ожидания видно, через сколько повтор.
- **Камеру отключили** — `ConnectionTracker.disappeared`. `teardown()` останавливает все задачи этой камеры, закрывает транспорт и сбрасывает состояние. Если подключена другая камера Sony, программа переходит к ней.
- **Сеанс оборвался сам** (поток свойств закончился) — то же, что сорвавшаяся попытка.

**По Wi-Fi.** Пока камеры нет на кабеле, раз в секунду работает `wifiTick()`: сначала пробует адрес, где камера была в прошлый раз (`Prefs.wifiHost`), потом ищет по SSDP. `tryWiFi(host)` подключает `PTPIPTransport` (на приветствие — 5 с, при сопряжении — 60: камера ждёт подтверждения на экране) и запускает тот же `runSession`, что и для USB. Появилась камера на кабеле — Wi-Fi закрывается, USB важнее. Отказ «не сопряжено» и камера, которая держит прошлое подключение (три неудачи подряд), показываются на экране ожидания.
### Свойства

`CameraSession` хранит последний разбор `0x9209` и отдаёт каждый новый снимок свойств в поток `snapshots`. Перечитывание запускают:

- событие `0xC203` от камеры — в том числе когда крутят колёса на самой камере;
- ожидание подтверждения записи — каждые 150 мс.

`CameraController.apply` кладёт снимок в `properties`, обновляет признак записи видео и снимает отметку «ждёт подтверждения» с настроек, которые уже пришли к нужному значению. Интерфейс всегда показывает значения из камеры, а не запрошенные.

### Изменение настройки

```
клик / стрелка / колесо
  → CameraController.request(id, value)       запоминает цель, ставит отметку pending
  → WriteCoalescer.submit(code, value)        одна запись на свойство, промежуточные значения схлопываются
  → CameraSession.set(code, value)            проверяет, что можно менять и значение допустимо;
                                              шлёт 0x9205 и ждёт подтверждения чтением (до 2,5 с)
  → CameraController.writeFinished / apply    снимает отметку pending
```

`requestStep` (стрелки, колесо) считает соседнее значение от последнего запрошенного, а не от подтверждённого. Иначе быстрые шаги упирались бы в ожидание камеры.

`isWritable(id)` разрешает изменение, только если фаза `ready`, не идёт применение пресета или съёмка и камера отдаёт свойство как изменяемое.

### Превью и гистограмма

Две задачи. Первая в цикле вызывает `CameraSession.nextLiveViewFrame()` и кладёт кадр в `AsyncStream` с буфером на один, самый свежий, кадр. Метод сам повторяет запрос при AccessDenied, DeviceBusy и InvalidObjectHandle. Вторая берёт кадр из потока: так следующий кадр запрашивается, пока текущий декодируется, — по Wi-Fi это 25 кадров/с вместо ~22. Кадр декодируется в `CGImage`, по уменьшенной до 128×72 копии считается гистограмма (64 столбца, яркость по Rec. 709), затем кадр уходит на главный поток.

Временные ошибки не останавливают цикл: пауза растёт от 100 мс до секунды. Цикл заканчивается только при отключении или отмене. Раз в полсекунды пересчитываются частота кадров (за последние 2 с), признак «кадры не приходят больше 1,5 с» и числа для плашки: `shownFPS` и `frameGapMs` — самая долгая пауза между кадрами за 10 с. Подсказка о подключении берёт адреса и сигнал из `connectionDetails()`: адрес камеры и Mac — из `PTPIPTransport`, сигнал — CoreWLAN (без разрешения на геолокацию).

### Запись видео

`CameraSession.toggleRecording()` нажимает и отпускает кнопку записи и ждёт, пока изменится `0xD21D`. Время начала записи для таймера берётся из момента, когда `0xD21D` стал 1.

### Снимок

`CameraController.capturePhoto()`:

1. Если на экране включён просмотр, сразу показывает кадр превью.
2. Если место сохранения в камере (`0xD222`) не совпадает с настройкой программы, записывает его.
3. `CameraSession.capturePhoto(download:)` делает S1 → фокус → S2 и отпускание. Если шаг сорвался, отпускает обе кнопки. При сохранении на Mac скачивает все объекты снимка.
4. Пишет файлы в папку из настроек, не затирая существующие (`FileNaming.unique`).
5. Строит картинку для просмотра (до 2048 px) и миниатюру для ленты через ImageIO. JPEG предпочтительнее RAW: он быстрее.
6. Добавляет снимок в ленту и показывает его на заданное время.

`grabFrame()` сохраняет последний JPEG превью как есть: камеру не трогает, поэтому работает и во время записи.

Переключение фото ↔ видео — обычная запись режима съёмки `0x500E`. Пару с той же буквой даёт `CaptureMode.counterpart`.

### Пресеты

- `PresetCatalog.capture` берёт текущие значения 14 настроек, если камера сейчас даёт их менять.
- Пресеты хранятся JSON-ом в `UserDefaults` под ключом `presets`.
- `CameraSession.apply` применяет настройки по одной в порядке `PresetCatalog.order` и пропускает совпадающие значения.
- Зависимые настройки (`PresetCatalog.dependency`) пропускаются, если не применилась базовая: температура и сдвиги — от баланса белого, экспокоррекция — от ISO.
- Итог — списки «применено» и «не удалось».

### Настройки программы

`Prefs` — тонкая обёртка над `UserDefaults`:

| Ключ | Значение |
|---|---|
| `photoDestination` | `macAndCard` / `macOnly` / `cardOnly` |
| `photoFolder` | путь к папке |
| `reviewEnabled` | показывать ли снимок после съёмки |
| `reviewSeconds` | 1…10 |
| `reviewSource` | `downloaded` / `camera` |
| `autoHideControls` | автоскрытие элементов |
| `autoHideSeconds` | через сколько секунд прятать, 1…30 |
| `wifiEnabled` | подключаться по Wi-Fi, когда камеры нет на кабеле |
| `wifiHost`, `wifiCameraName` | где и какая камера была по Wi-Fi в прошлый раз |

`ScreenState` хранит в `UserDefaults` только включённую гистограмму (`histogramOn`).

### Потоки и параллельность

- `CameraSession` — actor: команды к камере идут строго по одной.
- `CameraController`, `ScreenState` и весь интерфейс — на главном потоке (`@MainActor`).
- Цикл превью — две отдельные задачи (запрос и декодирование): декодирование и гистограмма не тормозят ни интерфейс, ни запрос следующего кадра.
- `PTPIPTransport` — actor, как и `CameraSession`; его каналы `NWConnection` работают на своих очередях и отдают пакеты через ожидающих с тайм-аутом.
- Колбэки ImageCaptureCore приходят на потоки системы. `ICCameraTransport` переводит их в `async`/`await` и поток событий; повторный ответ после таймаута отсекает `Once`.

## Тесты

```bash
swift test
```

Модульные тесты на Swift Testing покрывают `ZVCore` (85 тестов): разбор PTP и ответов Sony, рукопожатие, запись с подтверждением, превью, пресеты, съёмку, имена файлов, гистограмму, разбор HTTP и команды API, политику переподключения, фильтры ввода, пакеты PTP/IP и SSDP, цветовую температуру по режиму баланса белого.

- `FakeCamera` — поддельная камера, реализует `PTPTransport`. Хранит свойства и применяет записи. Отдаёт заданные кадры превью и «снимает» заданные файлы. Умеет оборвать связь на нужной команде и ответить DeviceBusy на нажатие кнопки.
- `Fixtures/` — настоящие ответы камеры: `deviceinfo.bin` (серийный номер обнулён), `sony_extdeviceinfo.bin`, `props_settled.bin`, `lv_frame_raw.bin`.
- `SessionTiming.test` — короткие тайминги, чтобы тесты шли доли секунды.

Сквозные тесты на настоящей камере идут через [API автоматизации](automation-api.md):

| Скрипт | Что проверяет |
|---|---|
| `scripts/e2e.py <папка>` | токен и ошибки API, превью, меню Fn, все настройки, изменение настроек, гистограмма, пресеты; 35 проверок |
| `scripts/e2e_photo.py <папка>` | фото ↔ видео, снимки RAW+JPEG со скачиванием, просмотр, лента, стоп-кадр, скрытие элементов; 26 проверок |

Оба скрипта проходят и по USB, и по Wi-Fi: программа подключается сама, как камера доступна. Оба запоминают исходные настройки камеры и программы и в конце возвращают их, проверяя чтением. `e2e_photo.py` снимает «только на Mac» во временную папку, поэтому на карту ничего не пишется. В папку результатов они кладут скриншоты окна.

Перед запуском соберите программу и откройте её с API:

```bash
scripts/build-app.sh
open "build/ZV-E10 Viewer.app" --args --automation
mkdir -p /tmp/zv-e2e && scripts/e2e.py /tmp/zv-e2e
```

## Сборка и выпуск

| Скрипт | Что делает |
|---|---|
| `scripts/build-app.sh` | release-сборка, бандл `build/ZV-E10 Viewer.app`: бинарник, `Resources/Info.plist`, иконка; подпись ad-hoc |
| `scripts/make-dmg.sh` | `build/ZV-E10-Viewer.dmg`: программа и ссылка на «Программы» |
| `scripts/make-icon.sh` | пересобирает иконку из `Resources/AppIcon.icon` (Icon Composer) в `Resources/Assets.car` и `Resources/AppIcon.icns`; нужен Xcode 26 |

Готовые файлы иконки лежат в репозитории, поэтому обычной сборке Xcode 26 не нужен.

Выпуск новой версии:

1. Поднять `CFBundleShortVersionString` и `CFBundleVersion` в `Resources/Info.plist`.
2. `swift test`, при подключённой камере — сквозные тесты.
3. `scripts/make-dmg.sh`, проверить образ: `hdiutil verify`, запуск программы из образа.
4. Коммит, тег `vX.Y.Z`, `git push origin main vX.Y.Z`.
5. `gh release create vX.Y.Z build/ZV-E10-Viewer.dmg --title "ZV-E10 Viewer X.Y.Z" --notes-file <файл>`.

Сборка только под Apple Silicon (arm64). Подписи разработчика и нотаризации нет: программа подписана ad-hoc, установка описана в [README](../README.md#установка-на-mac).

## Утилита zv-probe

```bash
swift run zv-probe info                      # модель, прошивка, включён ли PC Remote
swift run zv-probe props                     # все 24 настройки с подписями
swift run zv-probe lv 100 /tmp/frame.jpg     # 100 кадров превью: частота и размер, последний кадр — в файл
swift run zv-probe set 0xD26A 2              # записать свойство и проверить, приняла ли камера
swift run zv-probe rec                       # начать запись и через 2 с остановить
```

Утилита ждёт камеру до 30 секунд. Пока она работает, программа должна быть закрыта: с камерой работает только кто-то один. `set` и `rec` меняют состояние камеры: прочитайте исходное значение и потом верните его.

## Соглашения

- Swift 6 toolchain, режим языка Swift 5, macOS 14 и новее.
- Комментарии и тексты интерфейса — на русском.
- Новая логика — сначала тест в `ZVCoreTests` на `FakeCamera`, потом код. Интерфейс проверяется через API автоматизации и скриншоты.
- Камеру ничем не трогать без причины: программа не меняет то, чего не касался пользователь.
- Серийный номер камеры не должен попадать в репозиторий: дампы `DeviceInfo` содержат его, в фикстурах он обнулён.

Исходное описание проекта и план разработки — в `docs/superpowers/specs` и `docs/superpowers/plans`.

## Частые доработки

**Новая настройка.**

1. Код свойства — в `SonyProp`.
2. Новый случай в `SettingID`: код, `title`, при необходимости `shortTitle`.
3. Группа в `SettingGroup.settings`, при желании — место в `SettingCatalog`.
4. Подписи значений — в `ValueFormatter`, тест подписей — в `SettingsTests`.

Списки допустимых значений программа берёт из камеры.

**Подпись значения показывается как `#N`.** Для этого значения нет подписи в `ValueFormatter`: добавьте её, сверив с меню камеры.

**Другая камера Sony.** `CameraDiscovery` пропускает любую камеру Sony, рукопожатие общее. У камер примерно с 2020 года (протокол 3.00, как у ZV-E10) отличаться будут в основном наборы значений: проверьте подписи через `zv-probe props` и меню камеры. Для камер постарше (протокол 2) нужно:

- читать версию протокола из ответа `0x9202` (`SonyExtInfo.version`);
- для версии 2 менять выдержку, ISO и экспокоррекцию шагами, как это делает libgphoto2;
- не считать ошибкой пустой ответ `0x9202` и отказ записи PriorityMode.

Подробности — в [Протоколе камеры](protocol.md#другие-камеры-sony).

**Новая команда API.** Случай в `AutomationAction` с разбором из JSON и тестом в `AutomationTests`, выполнение — в `AutomationServer.perform`, описание — в [API автоматизации](automation-api.md).

## Приложение для Android

Папка `android/` — отдельный Gradle-проект: Kotlin, Jetpack Compose, minSdk 29, без сторонних библиотек кроме AndroidX. Логика та же, что в `ZVCore`, перенесена один в один, — те же имена настроек, подписи, пресеты, тайминги.

| Папка `app/src/main/java/local/zve10viewer/` | Что внутри | Аналог на Mac |
|---|---|---|
| `ptp/` | `ByteReader`, `PtpValue`, контейнеры PTP, `PtpTransport` | `ZVCore/PTP` |
| `sony/` | коды Sony, `DeviceInfo`, свойства из `0x9209`, кадр превью, `ObjectInfo` | `ZVCore/Sony` |
| `session/` | `CameraSession` на корутинах | `ZVCore/Session` |
| `settings/` | настройки, подписи, раскладка Fn, пресеты, `WriteCoalescer`, имена файлов, гистограмма | `ZVCore/Settings`, `Presets`, `Photo` |
| `usb/` | `UsbPtpTransport` — PTP поверх Android USB host | `ZVCamera/ICCameraTransport` |
| `ptp/PtpIp.kt` | пакеты PTP/IP, сборка пакетов из потока, ответ на операцию, SSDP | `ZVCore/PTPIP` |
| `wifi/` | `PtpIpTransport` — PTP/IP на сокетах, `PtpIpIdentity` — GUID в SharedPreferences, `WiFiDiscovery` — SSDP | `ZVCamera/PTPIPTransport` |
| `CameraController`, `Storage` | состояние программы, настройки, сохранение в MediaStore | `ZVViewer/CameraController`, `Prefs` |
| `ui/` | экраны на Compose | `ZVViewer` |

Тесты — `app/src/test`: 45 тестов на JVM на тех же дампах камеры, плюс `FakeCamera`, которая хранит свойства и применяет записи; отдельно — пакеты PTP/IP и цветовая температура.

Отличия Wi-Fi на Android от Mac:

- **`TCP_QUICKACK`** перед каждым чтением сокета команд: без него Android откладывал подтверждение TCP, камера держила короткий ответ «кадр не готов», и превью было 16–19 кадров/с вместо 25 (подробно — в [Протоколе камеры](protocol.md#wi-fi-ptpip)).
- **Сборщик пакетов** растит буфер удвоением, а не склеивает массивы на каждом куске: камера шлёт файл пакетами по 2 МБ, а TCP отдаёт их по 1–60 КБ.
- **Превью** — та же пара «запрос → канал с одним свежим кадром → декодирование», что на Mac.
- Своё сопряжение: GUID планшета другой, камера помнит его отдельно от Mac.

```bash
cd android
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home   # если JDK 17 не по умолчанию
./gradlew :app:testDebugUnitTest :app:assembleDebug
scripts/adb_install.py <устройство> app/build/outputs/apk/debug/app-debug.apk
```

Вспомогательные скрипты в `android/scripts`:

- `adb_install.py` — ставит APK и сам нажимает подтверждение установки HyperOS/MIUI;
- `adb_tap.py` — ждёт на экране кнопку с нужной надписью и нажимает её;
- `adb_ui.py` — тексты на экране программы с координатами.

Так программу можно проверять на планшете без рук: Compose отдаёт тексты системе специальных возможностей, и `uiautomator` их видит. Автоскрытие элементов мешает таким проверкам — на время проверки его удобно выключить в настройках. Планшет при этом можно держать в сети по adb через Wi-Fi (`adb tcpip 5555`, затем `adb connect <адрес>:5555`), а разъём оставить камере.

Релизная сборка подписывается ключом отладки (`~/.android/debug.keystore`): так она ставится поверх отладочной без потери настроек. Для настоящего публичного выпуска стоит завести отдельный ключ и хранить его.

Чем подключение по USB на Android отличается от ImageCaptureCore на Mac — в [Протоколе камеры](protocol.md#usb-напрямую-android).
