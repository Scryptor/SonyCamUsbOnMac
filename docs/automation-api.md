# API автоматизации

Sony Cam Viewer умеет принимать команды по локальному HTTP. Через API можно:

- узнать состояние камеры и экрана;
- нажимать те же кнопки, что и мышью;
- менять настройки камеры и программы;
- снимать скриншоты окна и кадры превью.

API сделан для автоматических тестов и скриптов. По умолчанию он выключен.

## Включение

Запустите программу с флагом `--automation`:

```bash
open "/Applications/Sony Cam Viewer.app" --args --automation
```

Если программа уже запущена, сначала закройте её: уже запущенной программе `open` флаг не передаст.

Если запускать сам исполняемый файл `Sony Cam Viewer.app/Contents/MacOS/ZVViewer`, вместо флага можно задать переменную окружения `ZV_AUTOMATION=1`. Порт по умолчанию — 47811, другой задаётся переменной `ZV_AUTOMATION_PORT`.

При запуске программа создаёт случайный токен и записывает порт и токен в файл, который может читать только текущий пользователь:

```
~/Library/Application Support/Sony Cam Viewer/automation.json
{"port": 47811, "token": "…"}
```

Токен меняется при каждом запуске.

Пока API включён, macOS не усыпляет программу (App Nap), даже если её окно закрыто другими: иначе таймеры растягиваются и превью падает до 6–12 кадров/с, а тесты начинают зависеть от того, что открыто на экране. Пока идёт сеанс с камерой, программа держит это и без API.

Только вместе с API действует переменная `ZV_PTPIP_HOST`: по Wi-Fi программа подключается лишь к этому адресу, без поиска камеры в сети. Так тесты гонят связь через прокси «плохого Wi-Fi» `scripts/badnet.py` (см. `scripts/wifi_resilience.py`). Адрес — `хост` или `хост:порт`: порт отличается от 15740 только у виртуальных камер.

Виртуальные камеры — `scripts/fake_camera.py` (одна) и `scripts/fake_cameras.py` (A, B, C… на соседних портах, все разные и отвечают на поиск в сети). С ними программу запускают без `ZV_PTPIP_HOST`: она находит их поиском, как настоящие. Сквозные тесты — `scripts/e2e_cameras.py` (выбор камеры), `scripts/e2e_strip.py` (лента камер) и `scripts/e2e_group.py` (группа; `scripts/fake_cameras.py --reject C:iso --slow-record C` — камера C не меняет ISO, а запись у неё начинается и останавливается за 2 с). Виртуальная камера, как настоящая, открывает цветовую температуру только в режиме «Цвет. темп.». Инструменты монитора проверяет `scripts/e2e_monitor.py` (зебра, false color, пикинг при увеличении, рамки, меню, волновая форма, наложение кадра), фокус и зум с экрана — `scripts/e2e_lens.py` (виртуальная камера знает точку AF, касание, Near/Far и зум). Кнопку записи проверяет `scripts/e2e_record.py`: он запускает `scripts/fake_camera.py --record <сценарий>` (камера занята, бросает запись, выполняет отпускание во время старта — `release-race` и другие) и снимает `/state` каждые 40 мс.

## Запросы и ответы

- Сервер слушает только `127.0.0.1`: с других компьютеров он недоступен.
- Каждый запрос должен нести заголовок `X-ZV-Token: <токен>` или параметр `?token=<токен>` в адресе.
- После ответа сервер закрывает соединение: один запрос — одно соединение.
- Тело запроса — JSON, не больше 64 КБ, с заголовком `Content-Length`.

| Код | Когда |
|---|---|
| 200 | готово |
| 400 | запрос не разобран: битый HTTP или JSON, неизвестная команда, не хватает параметра |
| 401 | нет токена или он неверный |
| 404 | неизвестный путь |
| 409 | команду сейчас выполнить нельзя; в ответе `{"error": "…"}` с причиной |

Ошибки приходят в виде `{"error": "текст"}`.

Команды выполняются так же, как нажатия кнопок: ответ 200 значит «команда принята», а не «камера уже применила». Чтобы дождаться результата, опрашивайте `/state`. Например, ждите, пока у настройки пропадёт `pending` и `value` станет нужным.

## GET /state

Состояние программы и камеры в JSON.

| Поле | Тип | Что это |
|---|---|---|
| `phase` | строка | `searching` — ищет камеру, `notPCRemote` — камера не в режиме PC Remote, `connecting` — подключается, `settling` — первые секунды после подключения, `ready` — готова |
| `model`, `firmware` | строка или `null` | модель и прошивка камеры |
| `mode` | строка | `video` или `photo` — по режиму съёмки камеры (S&Q — тоже `video`) |
| `shootingMode` | строка | `photo`, `video` или `slowQuick` (S&Q) |
| `slowMotion` | объект или `null` | в S&Q: `captureFps` — частота съёмки (по самой длинной допустимой выдержке, `null`, если не видно) и `recordFps` — частота ролика |
| `recording` | bool | идёт запись видео |
| `recordingSeconds` | число или `null` | сколько секунд идёт запись |
| `capturing` | bool | идёт съёмка фото |
| `capture` | объект или `null` | где снимок: `phase` — `focusing`, `exposing` (камера отработала спуск) или `downloading`; у загрузки ещё `file`, `files`, `received`, `expected` (байты; `expected` — `null`, если размер неизвестен) и `caption` — подпись на кнопке, например «Загрузка 42 %» |
| `recordingRequest` | строка или `null` | запуск (`starting`) или остановка (`stopping`) записи с кнопки, пока камера не подтвердила; через 6 с без ответа — снова `null` и отказ в `recordingNotice` |
| `recordingNotice` | строка или `null` | отказ записи у кнопки, на месте «Запуск записи…» (5 с): «Камера занята — запись не началась», «Камера не начала запись», «Камера начала запись и сразу остановила», «Камера ещё не ответила на прошлое нажатие» и т.п. Запись, остановленную на камере, сообщает `status` |
| `journal` | массив строк | последние 30 записей журнала панели отладки, старые первыми: связь, качество превью, нажатия записи с ответом камеры |
| `feedback` | массив | последние события отклика (до 8, новые в конце) — для отладки анимаций: `accepted(…)`, `shutterFired`, `frameGrabbed(…)`, `shotAdded(…)`, `recordingStarted`, `recordingStopped`, `failed(…)` |
| `fps` | число | кадров превью в секунду за последние 2 с |
| `frameGapMs` | число | самая долгая пауза между кадрами превью за последние 10 с, мс |
| `link` | объект | как идёт связь: `state` — `ok`, `weak` (кадры запаздывают), `interrupted` (связь прервалась), `reconnecting` (сеанс восстанавливается); `seconds` — сколько длится `interrupted` или `reconnecting`; `quality` — качество превью по Wi-Fi (`high` 1024×576, `low` 640×360, `null` по USB); `reconnects` — сколько раз сеанс восстанавливался с запуска; `lastRecoverySeconds` — сколько заняло последнее восстановление (от обрыва до первого кадра); `throughputKBs` — поток превью за 5 с, КБ/с; `rttMs` — отклик камеры на пробу |
| `transport` | строка или `null` | как подключена камера: `usb` или `wifi` |
| `wifi` | объект | `enabled` — подключаться ли по Wi-Fi, `pairing` — идёт сопряжение, `host` и `cameraName` — где и какая камера была в прошлый раз, `status` — сообщение о Wi-Fi на экране ожидания или `null` |
| `frameSize` | `[ширина, высота]` | размер кадра превью; нет поля, пока кадров нет |
| `histogramBins` | число | 64, когда гистограмма посчитана, иначе 0 |
| `assistOverlay` | объект или `null` | растр зебры, false color и пикинга по последнему кадру: `width`, `height` — его размер, `region` — какая часть кадра (`x`, `y`, `width`, `height`, доли; при увеличении — видимая часть с запасом), `zebra` и `peaking` — сколько точек растра под зеброй и пикингом, %. `null` — эти инструменты выключены |
| `waveform` | объект или `null` | волновая форма последнего кадра: `mode` (`luma`, `parade`), `columns` (256 или 3 × 128), `white` — белое превью (234 или 255), `low` и `high` — самый тёмный и самый яркий уровень (0…255), где есть точки. `null` — выключена |
| `reference` | объект или `null` | эталон для наложения: `source` («кадр 12:04:31» или имя снимка), `width`, `height` |
| `lens` | объект | фокус и зум с экрана: `controls` — команды 0x9207, которые знает камера (`"0xD2DC"`…); `touchFocus` — как сейчас ставится фокус касанием: `areaPosition` (точка AF), `remoteTouch` (касание экрана камеры) или `null`; `touchCancel` — можно снять слежение; `zoom` — можно зумировать; `zoomDirection` — 1, −1 или 0; `zoomBar` — шкала зума (`boxes`, `box`, `position`, `fraction`) или `null`; `zoomScale` — «×1,3» или `null`; `focusScale` — шкала фокуса доступна (ручной фокус); `focalPosition` — где фокус, 0…100, или `null`; `focusFrames` — рамки фокуса камеры из кадра: `kind` (`focus`, `face`, `tracking`), `x`, `y` — центр, `width`, `height` (доли кадра), `focused` |
| `histogramStats` | объект или `null` | что видно по гистограмме, в процентах: `shadows`, `midtones`, `highlights` — доли третей шкалы; `clippedShadows` — почти чёрные точки; `clippedHighlights` — точки на белом; `mean` — средняя яркость. Шкала — от чёрного до белого превью: в видео белое — 234, в фото — 255 |
| `cableAccessHint` | bool | камера на шине USB, а macOS не отдаёт её программе дольше 5 с — ждёт «Разрешить» в окне доступа к съемным томам |
| `applyingPreset` | bool | применяется пресет |
| `status` | строка или `null` | сообщение справа от кнопок вверху слева, например «Сохранено в «Вечер»» или «Не удалось на «C»: ISO 51200» |
| `review` | объект или `null` | просмотр снимка после съёмки: `title`, `source` («Загруженный снимок», «Кадр с камеры»), `timed` (закроется сам), `hasImage`, `files` (пути) |
| `shots` | массив | снимки и стоп-кадры сессии, новые сначала: `title`, `files` |
| `prefs` | объект | настройки программы: `destination`, `folder`, `reviewEnabled`, `reviewSeconds`, `reviewSource`, `autoHide`, `autoHideSeconds`, `wifiAdaptiveQuality`, `tallyEnabled`, `tallyWidth`, `tallyOpacity`, `tallyBlink` |
| `cameraDestination` | число или `null` | куда камера сохраняет снимки (`0xD222`): 1 — Mac, 16 — карта, 17 — оба |
| `cameras` | массив | список камер, как в подсказке строки состояния: `id` (у знакомой — её отпечаток, иначе `usb:…` / `wifi:адрес`), `name`, `model`, `link` — `usb`, `wifi` или `null` (не видна), `host` и `port` (по Wi-Fi), `state` — `current`, `available`, `needsPairing`, `offline`, `stateLabel` — подпись («свободна», «сопрягаю…»), `detail` — как подключена, `paired`, `known` |
| `currentCamera` | строка или `null` | id камеры на связи (после того как она назвала себя) |
| `strip` | массив | лента камер, пусто — на связи одна: плитки сверху вниз, порядок постоянный (выбор главной его не меняет) — `id`, `name`, `main`, `connected`, `recording`, `battery`, `fps`, `linked` (в группе; у главной — главная в группе и ведёт её), `port` (у главной — если она по Wi-Fi), у камер ленты ещё `following` (повторяет за главной сейчас: она в группе, и главная тоже; главная не из группы — `false`, группа ждёт) и `values` — что на камере сейчас: `iso`, `shutter`, `aperture`, `whiteBalance`, `colorTemperature`, `exposureProgram`. В `cameras` у камеры ленты `state` — `side` |
| `cameraName` | строка | имя камеры в строке состояния: своё, иначе модель |
| `pairing` | bool | идёт сопряжение |
| `presetMode` | строка | чьи пресеты показаны: `photo` или `video` (S&Q — тоже `video`); без камеры — режим, в котором она была |
| `presets` | массив | пресеты этого режима — номера во всех командах считаются в нём: `name`; `mode`; `values` — словарь «настройка → значение»; `skip` — настройки, которые пресет не меняет; `summary` — что он ставит, строкой, как в списке; `active` — стоит ли он сейчас на камере |
| `presetCounts` | объект | сколько пресетов у каждого режима: `{"photo": 2, "video": 3}` |
| `activePreset` | число или `null` | номер (с 0) первого пресета, который стоит на камере |
| `currentPreset` | число или `null` | текущий пресет — его имя на кнопке пресетов: последний применённый, созданный или сохранённый в этом режиме, если на камере не стоит другой |
| `presetModified` | bool | текущий пресет изменён: на камере поменяли то, что он ставит (и камера даёт это менять) |
| `presetChanges` | массив строк | что именно: `["ISO 800 → 1600", "1/50 → 1/100"]` |
| `previewingPreset` | число или `null` | какой пресет сейчас в быстром просмотре («Посмотреть» держат или камера ещё возвращается) |
| `previewReturning` | bool | кнопку отпустили, камера возвращается как была |
| `ui` | объект | что на экране: `fnOpen`, `allSettingsOpen`, `selected`, `group`, `editing` (если открыта строка), `info` (если открыта подсказка из плашки: `connection`, `frames` или `slowMotion`), `histogram`, `histogramPosition` — где гистограмма (`x`, `y` — доли свободного места; `null` — на месте по умолчанию), `controlsHidden`, `manualHidden`, `debug` — открыта ли панель отладки, `debugTab` — её вкладка, `gallery` — открытая галерея (`index` снимка в `shots`, `title`) или `null`, `zoom` — цифровое увеличение (`factor`, `centerX`, `centerY` — точка кадра в центре экрана, доли), `statusBar` — строка состояния: `pinned` — закреплена ли, `visible` — видна ли сейчас (вместе с элементами или закреплённая), `presetMenu` — открыт ли список пресетов, `presetNaming` — открыто ли окошко «Новый пресет», `presetSaving` — окошко «Сохранить настройки», `presetPeeking` — держат ли «Посмотреть», `presetsWindow` — окно «Пресеты» (`selected` — выбранный в нём пресет) или `null`, `assist` — меню «Монитор»: `open`, `selected` (выбранная плитка), `values` — значения всех инструментов, `waveform` — волновая форма: `on`, `mode`, `position` (доли свободного места или `null`), `touchFocus` — горит ли кнопка фокуса касанием |
| `settings` | массив | все 24 настройки, см. ниже |

Элемент `settings`:

| Поле | Что это |
|---|---|
| `id` | идентификатор настройки, см. список ниже |
| `code` | код свойства камеры, например `"0x5005"` |
| `title` | название, как в программе |
| `label` | значение, как его показывает программа, например `"1/50"`. У баланса белого в режиме «Цвет. темп.» — температура (`"7400 K"`), у цветовой температуры вне этого режима — `"≈ 5600 K"` или `"авто"` |
| `value` | значение в кодировке камеры (число); нет поля, если камера его не отдала |
| `writable` | можно ли менять прямо сейчас |
| `pending` | запрошено новое значение, камера его ещё не подтвердила |
| `options` | допустимые значения: `[{"value": …, "label": …}]`; пустой список, если менять нельзя; нет поля, если камера не отдала свойство. У `movieRecordingSetting` — режимы записи обоих форматов («4K 25p 100M», «HD 100p 100M»…), `value` — код режима: формат × 256 + параметры |
| `mode` | только у `movieRecordingSetting`: код текущего режима записи в той же кодировке |

Идентификаторы настроек: `exposureProgram`, `shutter`, `aperture`, `iso`, `exposureComp`, `metering`, `dro`, `focusMode`, `focusArea`, `whiteBalance`, `colorTemperature`, `wbShiftAB`, `wbShiftGM`, `creativeStyle`, `pictureProfile`, `movieFileFormat`, `movieRecordingSetting`, `imageSize`, `aspectRatio`, `fileFormat`, `jpegQuality`, `battery`, `cardRemaining`, `overheat`.

Группы для `openAllSettings`: `exposure`, `focus`, `color`, `video`, `photo`, `camera`.

Значения в кодировке камеры описаны в [Протоколе камеры](protocol.md#значения-свойств).

## POST /action

Тело — `{"action": "<команда>", …параметры}`. Ответ 200 — `{"ok": true}`.

### Экран

| Команда | Параметры | Что делает |
|---|---|---|
| `key` | `key`: `"f"`, `"m"`, `"z"`, `"p"`, `"c"`, `"escape"`, `"left"`, `"right"`, `"1"`…`"9"` | как клавиша: меню Fn, меню «Монитор», зебра, пикинг, false color, закрыть, шаг значения (только при открытом меню Fn или «Монитор»), пресет по номеру |
| `openFn` | `setting` — необязательно | открыть меню Fn, при указанной настройке — сразу на ней |
| `closeOverlays` | — | закрыть меню Fn и «Все настройки» |
| `select` | `setting` | выбрать настройку в меню Fn; 409, если её сейчас нельзя менять |
| `openAllSettings` | `group` — необязательно | открыть «Все настройки», при указанной группе — на ней |
| `editRow` | `setting` — необязательно | открыть ленту значений у строки в «Все настройки»; без параметра — закрыть |
| `toggleHistogram` | — | включить или выключить гистограмму |
| `toggleStatusPin` | — | закрепить или открепить строку состояния (кнопка с точкой и Wi-Fi вверху слева): закреплённая остаётся на экране, когда элементы спрятаны; вместе с элементами строка видна всегда |
| `toggleControls` | — | как клавиша H: спрятать или показать элементы |
| `dismissReview` | — | закрыть просмотр снимка |
| `openShot`, `openGallery` | `index` (у `openGallery` необязательно, по умолчанию 0) | открыть галерею на снимке из ленты (0 — самый новый) |
| `galleryStep` | `offset` (число) | соседний снимок в галерее: +1 — старше, −1 — новее; 409, если галерея закрыта |
| `closeGallery` | — | закрыть галерею |
| `moveHistogram` | `x`, `y` — доли от 0 до 1 | поставить гистограмму: 0 — у левого (верхнего) отступа, 1 — у правого (нижнего) |
| `setZoom` | `factor` (1…8), `x`, `y` — необязательно, точка кадра (доли) в центре экрана | цифровое увеличение live view, как щипок; ниже 1,05 — весь кадр. 409, если кадров нет |
| `resetZoom` | — | вернуть весь кадр |
| `toggleWaveform` | — | включить или выключить волновую форму |
| `waveformMode` | `mode`: `"luma"` или `"parade"` | яркость или RGB-парад; другое — 409 |

### Настройки камеры

| Команда | Параметры | Что делает |
|---|---|---|
| `request` | `setting`, `value` (число) | поставить значение; 409, если настройку сейчас нельзя менять. Значение должно быть из `options`, иначе камера его не получит. `colorTemperature` работает как ползунок: вне режима «Цвет. темп.» камера сначала переключается в него; значение вне диапазона камеры — 409, и режим не меняется. `movieRecordingSetting` с кодом режима из `options` сам переключит формат видео, если нужно; пока камера идёт к режиму, у настройки `pending`, а `mode` — то, что на камере сейчас. `movieFileFormat` меняет режим целиком: в другом формате берётся та же частота с самым высоким битрейтом |

## GET /screenshot и GET /frame

- `GET /screenshot` — PNG окна программы, каким оно выглядит сейчас, вместе с открытой подсказкой из плашки (popover дорисовывается на своё место, фон у него — тёмная плашка вместо системного размытия). Снимается самим окном, поэтому разрешение на запись экрана не нужно. `GET /screenshot?window=presets` — так же окно «Пресеты». 409, если окна нет.
- `GET /frame` — последний кадр превью в JPEG, как он пришёл с камеры. 409, если кадров ещё нет.

## Примеры

Проще всего — `scripts/zvapi.py`: он сам читает порт и токен.

```bash
scripts/zvapi.py GET /state
scripts/zvapi.py POST /action '{"action": "openFn", "setting": "whiteBalance"}'
scripts/zvapi.py GET /screenshot > window.png
scripts/zvapi.py GET /frame > frame.jpg
```

То же через curl:

```bash
INFO="$HOME/Library/Application Support/Sony Cam Viewer/automation.json"
PORT=$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["port"])' "$INFO")
TOKEN=$(python3 -c 'import json,sys; print(json.load(open(sys.argv[1]))["token"])' "$INFO")

curl -s -H "X-ZV-Token: $TOKEN" "http://127.0.0.1:$PORT/state"
curl -s -H "X-ZV-Token: $TOKEN" -d '{"action": "request", "setting": "iso", "value": 800}' "http://127.0.0.1:$PORT/action"
```

Поставить значение и дождаться подтверждения, на Python:

```python
import json, os, time, urllib.request

info = json.load(open(os.path.expanduser("~/Library/Application Support/Sony Cam Viewer/automation.json")))

def call(method, path, body=None):
    req = urllib.request.Request(f"http://127.0.0.1:{info['port']}{path}", method=method,
                                 data=json.dumps(body).encode() if body is not None else None)
    req.add_header("X-ZV-Token", info["token"])
    with urllib.request.urlopen(req, timeout=15) as r:
        return json.loads(r.read())

def setting(sid):
    return next(x for x in call("GET", "/state")["settings"] if x["id"] == sid)

call("POST", "/action", {"action": "request", "setting": "iso", "value": 800})
deadline = time.time() + 5
while time.time() < deadline and (setting("iso")["pending"] or setting("iso").get("value") != 800):
    time.sleep(0.2)
print(setting("iso")["label"])
```

Готовые сценарии — `scripts/e2e.py`, `scripts/e2e_photo.py` и `scripts/e2e_modes.py` для настоящей камеры, `scripts/e2e_cameras.py`, `scripts/e2e_strip.py`, `scripts/e2e_group.py` и `scripts/e2e_record.py` для виртуальных (см. [Устройство кода](architecture.md#тесты)).

## Безопасность

- Без флага `--automation` и без `ZV_AUTOMATION=1` сервер не запускается.
- Сервер слушает только `127.0.0.1`.
- Без токена ответ — 401. Токен случайный на каждый запуск, файл с ним доступен только текущему пользователю.
- Запись видео и снимок требуют `"confirm": true`.

API может менять настройки камеры. Если пишете свои сценарии, запоминайте исходные значения и возвращайте их в конце, как это делают `e2e.py`, `e2e_photo.py` и `e2e_modes.py`.
